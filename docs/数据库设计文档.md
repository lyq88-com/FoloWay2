# 数据库设计文档

> **项目**: AI习惯伙伴 (ai-habit-partner-v2)
> **版本**: v1.0
> **数据库**: MySQL 8.0+ / Redis 6.0+
> **建表脚本**: `server/sql/init.sql`（可直接执行）

---

## 一、概述

本文档定义 AI习惯伙伴 全部业务实体表结构、字段含义、关联关系、索引设计，以及 Redis 缓存键命名规范。

系统采用 **MySQL（持久化存储）+ Redis（缓存与会话）** 双存储架构：
- MySQL 存储所有业务核心数据，保证事务一致性
- Redis 存储短生命周期数据（验证码、Token、对话上下文、热点缓存），降低数据库压力

## 五、ER 关系图（文字描述）

```
users (1) ──< (N) habits              用户拥有多个习惯配置
users (1) ──< (N) checkins            用户每天一条打卡主记录
checkins (1) ──< (N) checkin_items    一条打卡主记录含多个习惯明细
users (1) ──< (N) difficulty_logs     用户的难度调整历史
users (1) ──< (N) chat_sessions       用户的对话会话
chat_sessions (1) ──< (N) chat_messages  会话包含多条消息
users (1) ──< (N) user_badges > (1) badges  用户解锁徽章
ai_roles (1) ──< (N) ai_role_assets   角色含多个表情素材
users (1) ──< (N) push_tasks          用户的推送任务
push_tasks (1) ──< (N) push_records   任务产生多次推送记录
users (1) ──< (N) daily_reports       用户的日报周报数据
admins (1) ──< (N) task_templates     管理员创建任务模板
```

**核心数据流**:
```
用户注册 → 选择习惯(habits) → 每日生成任务 → 打卡(checkins+checkin_items)
    → 动态难度调整(difficulty_logs) → AI对话(chat_sessions+chat_messages)
    → 统计周报(daily_reports) → 推送提醒(push_tasks+push_records)
    → 徽章解锁(user_badges)
```

## 六、Redis 缓存键设计

### 6.1 命名规范

所有键统一前缀 `ahp:`（ai-habit-partner），使用冒号 `:` 分隔层级：
```
ahp:{模块}:{标识}[:{子标识}]
```

### 6.2 键清单

| 键格式 | 用途 | 数据类型 | 过期时间 | 说明 |
|--------|------|----------|----------|------|
| `ahp:sms:code:{phone}` | 短信验证码 | String | 5分钟 | 发送验证码时写入，登录校验后删除 |
| `ahp:sms:limit:{phone}` | 短信发送频率限制 | String | 60秒 | 防止重复发送，值为发送时间戳 |
| `ahp:sms:count:{phone}` | 每日发送次数 | String | 24小时 | 超过10次禁止发送 |
| `ahp:token:user:{user_id}` | 用户登录Token | String | 7天 | 值为JWT，用于校验登录态 |
| `ahp:token:admin:{admin_id}` | 管理员Token | String | 2小时 | 管理后台登录态 |
| `ahp:habit:today:{user_id}` | 今日习惯任务缓存 | String(JSON) | 当天23:59:59 | 缓存getTodayHabit结果，避免重复计算 |
| `ahp:encourage:{user_id}:{date}` | 每日鼓励文案 | String | 当天23:59:59 | 每日只生成一次 |
| `ahp:streak:{user_id}` | 连续打卡天数 | String | 6小时 | 缓存计算结果，打卡后失效重建 |
| `ahp:chat:ctx:{user_id}` | AI对话上下文 | List | 1小时 | 存最近10条消息，LRPUSH+LTRIM |
| `ahp:chat:session:{user_id}` | 当前会话ID | String | 24小时 | 用户当前活跃会话 |
| `ahp:checkin:lock:{user_id}:{habit_id}:{date}` | 打卡防重锁 | String | 10秒 | 防止并发重复打卡 |
| `ahp:rate:{ip}:{api}` | 接口限流计数 | String | 60秒 | 滑动窗口限流，值为请求次数 |
| `ahp:badge:check:{user_id}` | 徽章检查锁 | String | 30秒 | 防止重复检查徽章解锁 |
| `ahp:report:{user_id}:{type}:{date}` | 报告缓存 | String(JSON) | 1小时 | 周报月报数据缓存 |
| `ahp:config:{key}` | 系统配置缓存 | Hash | 10分钟 | 缓存app_configs表，减少DB查询 |
| `ahp:online:{user_id}` | 用户在线状态 | String | 5分钟 | 心跳续期，用于推送判断 |

### 6.3 使用说明

**短信验证码流程**:
```
1. 发送: SET ahp:sms:code:{phone} {code} EX 300
         INCR ahp:sms:count:{phone} (EX 86400)
         SET ahp:sms:limit:{phone} 1 EX 60
2. 校验: GET ahp:sms:code:{phone} 比对 → 命中后 DEL
3. 频控: EXISTS ahp:sms:limit:{phone} → 存在则拒绝(60秒内已发)
         GET ahp:sms:count:{phone} → >10则拒绝(当日超限)
```

**AI对话上下文**:
```
1. 取上下文: LRANGE ahp:chat:ctx:{user_id} 0 9
2. 写入: RPUSH ahp:chat:ctx:{user_id} {json}
         LTRIM ahp:chat:ctx:{user_id} -10 -1  (保留最近10条)
         EXPIRE ahp:chat:ctx:{user_id} 3600
```

**今日习惯任务缓存**:
```
1. 查询: GET ahp:habit:today:{user_id} → 命中直接返回
2. 未命中: 查DB+计算难度 → SET ... EX {当天剩余秒数}
3. 打卡后: DEL ahp:habit:today:{user_id} (失效重建)
```

## 七、索引设计说明

### 7.1 索引策略

| 场景 | 索引 | 说明 |
|------|------|------|
| 唯一性约束 | `uk_phone`, `uk_username`, `uk_user_date` 等 | 防止重复数据 |
| 外键关联 | 所有FK字段自动建索引 | 加速JOIN和级联操作 |
| 范围查询 | `idx_date`, `idx_status_time` | 打卡日期范围、推送时间扫描 |
| 复合查询 | `idx_user_type`, `idx_user_date` | 覆盖高频查询条件 |

### 7.2 高频查询场景

| 查询 | 走索引 |
|------|--------|
| 查用户某天打卡 | `uk_user_date` (user_id + check_date) |
| 查用户近7天打卡 | `uk_user_date` 范围扫描 |
| 查用户习惯列表 | `idx_user` |
| 查待推送任务 | `idx_status_time` (status + scheduled_time) |
| 查会话消息 | `idx_session` (session_id + id) |
| 查操作日志 | `idx_created` |

## 八、设计说明与约定

1. **软删除**: 业务表用 `status` 字段（1启用/0停用）做软删除，不物理删除
2. **时间字段**: 统一 `created_at` / `updated_at`，DATETIME 类型，DEFAULT CURRENT_TIMESTAMP
3. **金额/百分比**: DECIMAL 类型，completion_rate 用 DECIMAL(5,2) 存百分比
4. **JSON字段**: breakdown / difficulty_targets / extra_data 用 MySQL JSON 类型
5. **外键策略**: 核心业务表（users→habits→checkins）加外键保证完整性；日志表（operation_logs, difficulty_logs）不加外键提升写入性能
6. **冗余字段**: checkin_items 冗余 user_id 和 habit_type，避免多表JOIN提升统计查询性能
7. **分表预留**: chat_messages 和 operation_logs 数据量大，后续可按月分表
